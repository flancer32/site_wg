# So, What Is the Ultimate Goal of Programming?

In this publication, I’ve endeavored to articulate my perspective on what constitutes the ultimate goal of programming. I’ve been involved in programming for about 25 years now, and finally, I’ve been able to answer this question for myself.

I would say that in programming, there are numerous goals, and the ultimate goal depends on the level of the programmer themselves. I’ll start with the simplest and move towards the more complex. Each subsequent goal encompasses all the previous ones. This is my subjective view, and someone else may have a different order of goals. Or even different goals altogether.

## The Writing

The goal is the text of the program, the code. This is such a basic level that even a beginner programmer, after writing several programs independently, ceases to perceive this as the ultimate goal.

## The Compiling

The next goal is a compiled program. Long ago, when there were no advanced IDEs, creating compilable (or error-free interpretable) programs was more challenging than it is now. I remember those times.

## The Running

Even a successfully compiled program may not work — division by zero, stack overflow, undefined, and so on. We create programs so that they work. And that’s also a goal, encompassing the two previous ones.

## The Usefulness

A program should not only start and stop at the user’s discretion. It should also perform certain functions useful to the user. Be useful to them. Solve the user’s business tasks.

## The Reading

One developer can easily write a small but useful program. When business requirements dictate creating a program of such a size that doing it alone is difficult, another goal arises. The program should be readable so that other developers can understand what it does.

## The Testing

If many people are involved in development, testing the program becomes relevant. To ensure that the changes made do not disrupt the functionality created by other developers. Adding tests to the application can significantly change the coding style and even influence the architecture of the application.

## The Modifying

If an application exists for a sufficiently long time, the ultimate goal of programming becomes creating changeable code. The application must adapt to changing environmental conditions, and its architecture and intra-team agreements should allow for changes to be made as simply as possible.

## Conclusion

In my view, there are many ultimate goals in programming. Like [Maslow’s hierarchy of needs](https://en.wikipedia.org/wiki/Maslow%27s_hierarchy_of_needs), they build upon one another.

What a specific programmer in a specific project considers the ultimate goal depends on both the programmer’s experience and the project itself. For example, in some projects, it simply doesn’t make sense to go beyond business goals (The Usefulness).

I’m sure there are higher ultimate goals, but with my experience, these are the ones I can see :)
