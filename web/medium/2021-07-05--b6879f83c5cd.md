# Фабрики объектов в JavaScript

Эта публикация — продолжение темы, начатой в статье про [порождение объектов](https://wiredgeese.com/%D0%BF%D0%BE%D1%80%D0%BE%D0%B6%D0%B4%D0%B5%D0%BD%D0%B8%D0%B5-%D0%BE%D0%B1%D1%8A%D0%B5%D0%BA%D1%82%D0%BE%D0%B2-%D0%B2-js-cf89130c97c5) в JavaScript, и попытка разобраться, что же лучше использовать в качестве Фабрики объектов — класс или функцию.

## Зачем нужна Фабрика?

Почему мы не можем просто использовать в коде оператор `new` или конструкцию `{}`?

const inst = new Clazz();

const obj = {};
Оператор `new` мы можем просто использовать в простых случаях — если у создаваемого объекта нет никаких зависимостей. Если же у создаваемого объекта есть зависимости:

class Dep1 {}

class Dep2 {}

class Clazz {

 dep1;

 dep2;

}
то оператор `new` становится использовать сложно. Приходится самостоятельно создавать все зависимости и передавать их в конструктор:

const dep1 = new Dep1();

const dep2 = new Dep2();

const inst = new Clazz(dep1, dep2);
или через свойства объекта:

class inst = new Clazz();

inst.dep1 = new Dep1();

inst.dep2 = new Dep2();
Фабрики объектов позволяют выстраивать иерархии, создающие объекты со всеми необходимыми зависимостями. В случае, если зависимость является простым объектом, то используется оператор `new`, а если зависимость сама является составным объектом, то используется Фабрика соответствующего объекта для этой зависимости. Разумеется, что иерархию Фабрик тоже нужно создавать — вручную или при помощи DI-контейнеров.

Чем же лучше ручное/контейнерное создание Фабрик такого же создания самих объектов? Дополнительный уровень абстракции добавляет бОльшую гибкость в приложение по отношению к изменениям. Польза от этой гибкости наблюдается лишь в больших, сложных приложениях. Если вы никогда не сталкивались с проблемами, которые возникают при непосредственном использовании оператора `new`, то вам Фабрики не нужны.

## Функция или класс?

Фабрика объектов для `Clazz` может быть реализована в виде функции:

function create() {

 const res = new Clazz();

 res.dep1 = new Dep1();

 res.dep2 = new Dep2();

 return res;

}

const inst = create();
Или в виде класса с методом `create` (или с любым другим названием — `build`, `make`, etc.):

class Factory {

 create() {

 const res = new Clazz();

 res.dep1 = new Dep1();

 res.dep2 = new Dep2();

 return res;

 }

}

const fact = new Factory();

const inst = fact.create();
Функциональный вариант выглядит более лаконичным (7 строк кода против 10 — на 30%). Но есть нюанс: Фабрика в общем случае сама нуждается в инициализации.

## Инициализация Фабрики

В случае классов инициализация Фабрики происходит в конструкторе:

class Factory {

 constructor(dep1Fact, dep2Fact) {

 this.create = function () {

 const res = new Clazz();

 res.dep1 = dep1Fact.create();

 res.dep2 = dep2Fact.create();

 return res;

 }

 }

}
Использование Фабрики выглядит так:

const dep1Fact = new FactoryDep1();

const dep2Fact = new FactoryDep2();

const clazzFact = new Factory(dep1Fact, dep2Fact);

const inst = clazzFact.create();
А таким образом происходит инициализация в случае фабричной функции:

function factory(dep1Fact, dep2Fact) {

 return function create () {

 const res = new Clazz();

 res.dep1 = dep1Fact();

 res.dep2 = dep2Fact();

 return res;

 }

}
и её использование:

const dep1Fact = factoryDep1();

const dep2Fact = factoryDep2();

const clazzFact = factory(dep1Fact, dep2Fact);

const inst = clazzFact();
Функциональный вариант (8 + 4 строки) всё равно выглядит лаконичнее (10 + 4).

## Помощь IDE

Я работаю с IDEA (PhpStorm). В ней поддержка аннотаций JSDoc реализована лучше, чем в VS Code (который, судя по всему, “заточен” под TypeScript, а к JSDoc’у относится довольно “прохладно”). Тем не менее даже в IDEA парсинг аннотаций работает не идеально (например, использование `@memberOf` приводит к [сбоям](https://youtrack.jetbrains.com/issue/WEB-41050) в анализе структуры кода).

Моё личное впечатление, что код, структурированный в виде классов, IDEA разбирает лучше. Так поиск использования метода класса `Factory.create` (“Find Usages” по Alt+F7) дает результаты:

export class Factory {

 constructor() {

 this.create = function () {}

 }

}
А поиск использования вложенной функции `factory.create`:

/**

 * [@param](http://twitter.com/param) dep1Fact

 * [@param](http://twitter.com/param) dep2Fact

 * [@return](http://twitter.com/return) {function(): Clazz}

 */

function factory(dep1Fact, dep2Fact) {

 /**

 * [@return](http://twitter.com/return) {Clazz}

 * [@memberOf](http://twitter.com/memberOf) factory

 */

 function create() {}

 return create;

}

/** [@type](http://twitter.com/type) {factory.create} */

const clazzFact = factory(dep1Fact, dep2Fact);
[результатов не даёт](https://youtrack.jetbrains.com/issue/WEB-50278) даже с учётом всевозможных аннотаций JSDoc.

Скорее всего, эту ошибку разработчики IDEA когда-нибудь исправят (или реализуют поиск по аннотациям не только классов, но и функций), но на данный момент использование классов в качестве Фабрик выглядит предпочтительнее с этой точки зрения.

## Резюме

Фабрики объектов увеличивают гибкость приложений по отношению к изменениям и демонстрируют эффект от их применения в сложных приложениях. Если объекты простые или их структуры неизменны во времени жизни приложения, то проще использовать оператор `new`.

Фабричная функция более лаконична по отношению к Фабрике-классу, но недостаточные на данный момент возможности различных IDE для разбора кода, документированного при помощи JSDoc, заставляют использовать Фабрики в виде классов.
