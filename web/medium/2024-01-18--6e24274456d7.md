# Code Types in TeqFW: Utilities

[Tequila Framework](https://flancer32.com/what-is-teqfw-45da7071fdd4) is my personal platform for developing web applications in pure JavaScript. In the series of publications “_Code Types in TeqFW_” I describe the typical code used in my development. The main goal of the series is to formalize the code patterns I use in my development. In this publication, I describe utilities.

A utility is essentially a “[pure function](https://en.wikipedia.org/wiki/Pure_function)” — a function that does not depend on the application’s state and does not modify the input arguments. For example, encoding/decoding functions like `btoa` and `atob`:

const b64 = btoa('text') 

const txt = atob(b64)
A typical pure function in JS looks something like this:

function util(a, b, c, d) {

 return x;

}
That is, the function takes a certain number of arguments as input and produces some result as output.

## The Class Notation

Usually, utilities can be grouped (e.g., formatting, working with dates, etc.), so it makes sense to group related functions in one ES6 module.

export function decode(data) { }

export function encode(data) { }
I use PHPStorm IDE for coding and notice that this IDE does not work well with auto-suggestions if the code is written in a functional style. Therefore, in my development, I use classes:

export class Util {

 decode(data) { }

 encode(data) { }

}
## Arguments and Results

Utilities usually relate to a small and stable functionality. Therefore, separate parameters are used as arguments rather than a single `opts` object:

function sum(a, b) {}
Using the decomposition of input parameters is very convenient if we need to change the order or quantity of input arguments. In the case of utilities, we usually know the number and order of input arguments quite well. The result is typically a single variable:

return z;
