# “Кровь” web-приложений

Самое ценное в любых приложениях — это данные. Как кровь циркулирует в живом организме, так и данные циркулируют в работающем приложении. В web-приложениях, в силу [их устройства](https://medium.com/@alex_gusev/%D0%BE%D1%81%D0%BD%D0%BE%D0%B2%D1%8B-web-%D0%BF%D1%80%D0%B8%D0%BB%D0%BE%D0%B6%D0%B5%D0%BD%D0%B8%D0%B9-b71709ec4530), данные должны передаваться по сети между фронтом и бэком.

![Image 2](img/d1a24935db14/image-01.gif)

Основным протоколом обмена данными между браузером и сервером является [HTTP](https://ru.wikipedia.org/wiki/HTTP), который передаёт данные в текстовом формате (бинарный формат появился с версии [HTTP/2](https://ru.wikipedia.org/wiki/HTTP/2)). Тестовый формат протокола обусловлен тем, что изначально он был предназначен для передачи именно текстовой информации — данных в формате [HTML](https://ru.wikipedia.org/wiki/HTML).

Дальнейшее развитие web’а сделало актуальным передачу не столько текстовых документов, сколько структурированных данных. На помощь HTML’у пришёл [XML](https://ru.wikipedia.org/wiki/XML) (так же, как и HTML, являющийся подмножеством [SGML](https://ru.wikipedia.org/wiki/SGML)):

<person>

 <firstName>Иван</firstName>

 <lastName>Иванов</lastName>

 <address>

 <streetAddress>Московское ш., 101, кв.101</streetAddress>

 <city>Ленинград</city>

 <postalCode>101101</postalCode>

 </address>

 <phoneNumbers>

 <phoneNumber>812 123-1234</phoneNumber>

 <phoneNumber>916 123-4567</phoneNumber>

 </phoneNumbers>

</person>
XML хорошо подходит для программной обработки (разбора структуры или её создания), но для людей (разработчиков) он слишком многословен. Поэтому, когда [Дуглас Крокфорд](https://ru.wikipedia.org/wiki/%D0%9A%D1%80%D0%BE%D0%BA%D1%84%D0%BE%D1%80%D0%B4,_%D0%94%D1%83%D0%B3%D0%BB%D0%B0%D1%81) предложил [JSON](https://ru.wikipedia.org/wiki/JSON) в качестве более “лёгкой” альтернативы XML’у, сообщество с энтузиазмом приняло новый формат:

{

 "firstName": "Иван",

 "lastName": "Иванов",

 "address": {

 "streetAddress": "Московское ш., 101, кв.101",

 "city": "Ленинград",

 "postalCode": 101101

 },

 "phoneNumbers": [

 "812 123-1234",

 "916 123-4567"

 ]

}
Данные в таком формате быстрее “загружаются” в голову разработчика при чтении и проще в описании при создании разработчиком документа. Дополнительным бонусом является то, что данные в таком формате легко преобразовываются в объекты JavaScript — единственного, по большому счёту, [языка программирования](https://medium.com/@alex_gusev/html-css-js-%D0%B2-web-%D0%BF%D1%80%D0%B8%D0%BB%D0%BE%D0%B6%D0%B5%D0%BD%D0%B8%D1%8F%D1%85-2f3fc8c9b00e), доступного в браузере.

JSON обходится всего шестью [типами](https://www.w3schools.com/JS/js_json_datatypes.asp) для описания всех данных:

*   строка
*   число
*   объект
*   массив
*   логический
*   null

И какую бы сложную структуру в backend’е не придумал разработчик, для передачи данных на фронт ему всё равно придётся приводить свою структуру к этим 6 типам.

К данным также можно отнести файлы для загрузки (downloads), медиа-контент (включая аудио- и видео-потоки). Даже HTML/CSS/JS-код при определённых условиях можно рассматривать как данные — например, если framework собирает конечную модель документа (DOM) из фрагментов, получаемых с сервера, то для него эти фрагменты являются данными.

Тем не менее, JSON, на мой взгляд, занимает особое место среди других форматов для описания данных, используемых в web-приложениях, и нужны веские причины, чтобы для передачи данных между фронтом и бэком использовать какой-то другой формат.
