# Адресация элементов в DOM

![Image 2](img/898acd38986/image-01.jpg)

Натолкнулся в хорошем учебнике [Learn JavaScript](https://learn.javascript.ru/) вот на [такой](https://learn.javascript.ru/introduction-browser-events) фрагмент кода:

<input id="elem" type="button" value="Нажми меня!">

<script>

 elem.onclick = function() {

 alert('Спасибо');

 };

</script>
Чем он примечателен? А тем, что в скрипте идёт обращение к переменной `elem` , которая не объявлялась в явном виде.

## Переменные в `globals`

Какой способ получения доступа к DOM-элементу по его идентификатору в JS первым приходит на ум? Лично мне — [document.getElementById()](https://developer.mozilla.org/ru/docs/Web/API/Document/getElementById):

let element = document.getElementById(id);
Но получается, что у нас и так в глобальной [области видимости](https://www.w3schools.com/js/js_scope.asp) (объект `window` в браузере) создаются элементы, доступные напрямую без всяких `getElementById()`.

А что будет, если идентификатор DOM-элемента имеет такое же значение, как какой-нибудь атрибут `window` ?

<span id="menubar">Menubar</span>

...

const fromGlobals = menubar;

const fromGlobalsAsProp = window['menubar'];

const fromDocById = document.getElementById("menubar");
В первых двух случаях мы получим объект `BarProp` и только в третьем случае DOM-элемент с идентификатором `menubar`.

Получается, что если мы в DOM добавляем элемент с идентификатором:

<input id="elem" ...>
то в глобальной области видимости появляется (если нет конфликта с именем `window`-атрибута) новая переменная с именем, совпадающим со значением атрибута `id`:

const myElem1 = elem;

const myElem2 = window.elem; // myElem1 === myElem2
А что будет, если мы в глобальной области видимости (`window`) создадим свойство, совпадающее по имени со значением идентификатора какого-либо элемента?

<div id="someId">...</div>

...

const someId1 = someId; // Element object

window.someId = "value";

const someId2 = someId; // "value"

const someId3 = document.getElementById("someId"); // Element object

(someId1 === someId3); // true
Любое свойство глобального объекта `window` делает невозможным доступ к переменной, созданной в глобальной области видимости в соответствии с идентификатором DOM-элемента.

Получается, что полагаться на данную особенность браузеров не стоит. Лучше использовать обычный способ:

document.getElementById("id")
## Применение идентификаторов

В описании функции `getElementById` сказано:

> Returns the first element within node’s descendants whose ID is elementId.

Во-первых, функция работает как по всему дереву документа (начиная с корня), так и для отдельной его части (начиная с любого элемента). Во-вторых, возвращается первый элемент с заданным идентификатором из множества существующих.

С одной стороны, идентификатор, по своей сути, должен однозначно адресовать элемент, с другой — функция `getElementById` допускает существование нескольких элементов с одинаковым `id` в DOM’е.

Спецификация HTML 4 [требует](https://www.w3.org/TR/html4/struct/global.html#adef-id), чтобы `id` был уникален для всего документа:

> This attribute assigns a name to an element. This name must be unique in a document.

Спецификация HTML 5 [говорит](https://html.spec.whatwg.org/multipage/infrastructure.html#home-subtree) о том, что id должен быть уникален в пределах “дерева” элементов:

> the id attribute value must be unique amongst all the IDs in the element’s tree

В [посте на stackoverflow](https://stackoverflow.com/questions/48240240/why-are-duplicate-ids-not-allowed-in-html) рекомендуют придерживаться подхода, когда идентификатор уникален для дерева всех элементов документа.

ОК, что получается, если мы собираемся твёрдо придерживаться этого подхода?

Получается, что идентификатором могут обладать элементы, которые явно будет в одном экземпляре на весь DOM. Т.е. элементы архитектурного уровня в браузерном приложении. Элементы web-компонентов, встраиваемые в DOM на уровне подгружаемых библиотек, не должны иметь идентификаторов вообще, т.к. мы не знаем, сколько компонентов может быть встроено в один и тот же DOM.

## Применение классов

Для определения роли различных элементов в пределах фрагмента DOM’а используются [классы](https://dom.spec.whatwg.org/#concept-class):

<div>

 <div class="v-layout">

 <div class="top">...</div>

 <div class="middle">...</div>

 <div class="bottom">...</div>

 </div>

 <div class="h-layout">

 <div class="left">...</div>

 <div class="middle">...</div>

 <div class="right">...</div>

 </div>

</div>
Например, у нас есть два компонента `v-layout` и `h-layout` , каждый из которых представляет различное размещение внутренних элементов в пределах компонента — вертикальное и горизонтальное. В обоих компонентах есть элемент класса `middle` . Если мы используем для доступа к `middle`-элементам функцию `getElementsByClassName()` на уровне документа, то мы получим массив из всех `middle`-элементов этого документа, что может быть лишено смысла (`middle`-элемент в вертикальном компоненте может иметь другую структуру, чем `middle`-элемент в горизонтальном компоненте).

Соответственно, при поиске DOM-элементов в компонентах мы должны “плясать” от корня компонента (`<div class=”v-layout”>` или `<div class=”h-layout”>`):

const root = document.getElementsByClassName("v-layout")[0];

const base = root.getElementsByClassName("base")[0];
Таким образом получается, что в переиспользуемых (_reusable_) компонентах мы не можем использовать идентификаторы для адресации DOM-элементов, а должны использовать классы. Т.е., атрибут`class` , помимо инструмента визуального оформления страницы (_уровень CSS_), получает так же роль инструмента манипулирования структурой и содержимым страницы (_уровень JavaScript_).

## CSS селекторы

Не очень удобно получать массив элементов по имени класса, зная, что на странице должен быть в точности один такой элемент. Для доступа к DOM-элементам API браузера предлагает также функции `querySelector()` и `querySelectorAll()`, где ключом для поиска элемента является [CSS-селектор](https://www.w3schools.com/cssref/css_selectors.asp).

Поиск base-элемента можно организовать так:

const base = document.querySelector(".v-layout .base");
`querySelector` также можно использовать и на уровне поддерева элементов:

const v = document.querySelector(".v-layout");

const base = v.querySelector(".base");
## Резюме

Идентификаторы можно использовать для элементов уровня приложения (которые должны быть в единичном экземпляре в DOM’е).

Для переиспользуемых компонентов нужно использовать классы для определения роли элемента в пределах компонента.

Для поиска элементов в DOM’е лучше использовать функцию `querySelector` , пусть она и [медленнее в два раза](https://gomakethings.com/javascript-selector-performance/#:~:text=getElementById()%20can%20run%20about,runs%207%2C000%20operations%20a%20millisecond.), чем `getElementById()` и `getElementsByClassName()`. Её гибкость и универсальность нивелирует проигрыш в скорости.
