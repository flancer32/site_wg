# Joined select with ‘knex’

![Image 2](img/2b0ea0ef2599/image-01.png)

‘[Knex.js](https://knexjs.org/)’ is a great library to interact with relational DBMS in `nodejs` apps (such as MySQL/MariaDB, PostgreSQL, MSSQL, Oracle, …). It is not an [ORM](https://en.wikipedia.org/wiki/Object%E2%80%93relational_mapping) tool, it is more like a [DAL](https://en.wikipedia.org/wiki/Data_access_layer) tool. In this post I will describe how to create `SELECT … JOIN …` queries using `knex`.

## Transaction

First of all, we need to get transaction to communicate with DB. This is a sample how to connect to DB, create transaction then close the connection:

import knex from 'knex';/** [@type](http://twitter.com/type) {Knex} */

const conn = await knex({

 client: '...',

 connection: {...}

});/** [@type](http://twitter.com/type) {Knex.Transaction} */

const trx = await conn.transaction();

try {

 // execute SQL here

 await trx.commit();

} catch (e) {

 await trx.rollback();

}await conn.destroy();
## Simple select

Select one record from a table:

const trx = await conn.transaction();

try {

 /** [@type](http://twitter.com/type) {Knex.QueryBuilder} */

 const query = trx.queryBuilder();

 query.table('app_task');

 query.select();

 query.where('id', 3);

 console.log('SQL: ' + query.toString());

 const rs = await query;

 for (const one of rs) console.log(one);

 await trx.commit();

} catch (e) {

 await trx.rollback();

 console.log(e);

}
Output:

SQL: select * from `app_task` where `id` = 3

{

 id: 3,

 ...

}
## Simple JOIN

In this sample I create SQL statement to select all data from 2 tables: `app_task`&`app_upload`:

const query = trx.queryBuilder();

// main table

query.table('app_task');

query.select();

// join another table

query.leftJoin('app_upload', 'app_upload.id', 'image_ref');

console.log('SQL: ' + query.toString());
This is result SQL:

select * from `app_task`

left join `app_upload` on

 `app_upload`.`id` = `image_ref`
## ‘Professional’ JOIN

Generally we need to join more than 2 tables and we need to use aliases for tables and selected columns (fields). In some cases we need to separate columns of the same names but from different tables in a query:

select

 app_task.id as taskId,

 app_upload.id as uploadId

from ...
Also the same table can be joined more than once in a query if it has different aliases:

left join `app_upload` as taskImg on taskImg.id=...

left join `app_upload` as userImg on userImg.id=...
This is a sample of the more complex JOIN:

_/* METADATA */

// tables_ const T_TASK = 'app_task';

const T_UPLOAD = 'app_upload';

const T_USER = 'app_user';

_// columns_ const T_TASK_A_DESC = 'desc';

const T_TASK_A_ID = 'id';

const T_TASK_A_IMAGE_REF = 'image_ref';

const T_TASK_A_TITLE = 'title';

const T_TASK_A_USER_REF = 'user_ref';

const T_UPLOAD_A_EXT = 'ext';

const T_UPLOAD_A_ID = 'id';

const T_UPLOAD_A_UUID = 'uuid';

const T_USER_A_ID = 'id';

const T_USER_A_NAME = 'name';
_/* ALIASES */

// for tables_ const asTask = 't';

const asUpload = 'up';

const asUser = 'usr';

_// for selected columns_ const aImageUuid = 'imgUuid';

const aTaskId = 'taskId';

const aTaskName = 'taskName';

const aUserName = 'userName';

_/* knex related objects */_ const tTask = {[asTask]: T_TASK}; _// "app\_task as t"_ const tUpload = {[asUpload]: T_UPLOAD}; _// "app\_upload as up"_ const tUser = {[asUser]: T_USER}; _// "app\_user as usr"
/** @type {Knex.QueryBuilder} */_ const query = trx.queryBuilder();

_// main table_ query.table(tTask);

query.select([

 {[aTaskId]: `${asTask}.${T_TASK_A_ID}`},

 {[aTaskName]: `${asTask}.${T_TASK_A_TITLE}`}

]);

_// join another table_ query.leftJoin(tUpload, `${asUpload}.${T_UPLOAD_A_ID}`, `${asTask}.${T_TASK_A_IMAGE_REF}`);

query.select([

 {[aImageUuid]: `${asUpload}.${T_UPLOAD_A_UUID}`}

]);

_// join more tables_ query.leftJoin(tUser, `${asUser}.${T_USER_A_ID}`, `${asTask}.${T_TASK_A_USER_REF}`);

query.select([

 {[aUserName]: `${asUser}.${T_USER_A_NAME}`}

]);

_// WHERE_ query.where(`${asTask}.${T_TASK_A_ID}`, 3);

Names for all tables and columns are metadata. It’s the same for all queries to the concrete DB. So, in the sample above I marked metadata with upper case: `T_TASK`, `T_TASK_A_ID`. In a real code it will be a external object that contains data for a table (name, attributes, indexes, keys).

Result SQL:

select

 `t`.`id` as `taskId`,

 `t`.`title` as `taskName`,

 `up`.`uuid` as `imgUuid`,

 `usr`.`name` as `userName`

from

 `app_task` as `t`

left join `app_upload` as `up` on

 `up`.`id` = `t`.`image_ref`

left join `app_user` as `usr` on

 `usr`.`id` = `t`.`user_ref`

where

 `t`.`id` = 3
## Resume

SQL is the base to interact with relational DBMS. `SELECT` with `JOIN` is used very often in applications and `knex` allows to create SQL of any complexity.
