# TeqFW DEM: основные файлы

В платформе [TeqFW](https://wiredgeese.com/%D1%87%D1%82%D0%BE-%D1%82%D0%B0%D0%BA%D0%BE%D0%B5-teqfw-208d5938205) для создания структур данных в реляционных базах (на серверной стороне) применяется [декларативное описание](https://wiredgeese.com/json-%D0%BE%D0%BF%D0%B8%D1%81%D0%B0%D0%BD%D0%B8%D0%B5-%D1%80%D0%B5%D0%BB%D1%8F%D1%86%D0%B8%D0%BE%D0%BD%D0%BD%D1%8B%D1%85-%D1%81%D1%82%D1%80%D1%83%D0%BA%D1%82%D1%83%D1%80-%D0%B4%D0%B0%D0%BD%D0%BD%D1%8B%D1%85-285a12c37f43) (DEM — Domain Entities Model). В этой публикации описывается, какие файлы и где нужно расположить, чтобы платформа могла взаимодействовать с реляционной БД.

## DEM-файлы

Каждый [плагин](https://wiredgeese.com/teqfw-%D1%82%D0%B5%D1%80%D0%BC%D0%B8%D0%BD%D1%8B-ffdf439a1079) в teq-приложении может иметь собственную структуру данных. Teq-приложение, как правило, ориентировано на работу с одной базой данных на серверной стороне. Это позволяет упростить приложение и обеспечить целостность данных в базе “_малой кровью_”. `dem`-файл с описанием схемы данных основной базы для каждого плагина находится в файле:

./etc/teqfw.schema.json
`dem`-файл для корневого плагина приложения (из него `npm` разворачивает приложение целиком) также находится в файле `./etc/teqfw.schema.json`.

## Map-файл

Так как каждый плагин имеет независимую от других схему данных, а связи между схемами могут выходить за пределы отдельного плагина (например, `sales`-плагин замыкается на `user`-плагин), то для разрешения подобных зависимостей используется `map`-файл. `map`-файл для основной базы данных находится в корневом плагине приложения, в файле:

./etc/teqfw.schema.map.json
В отличие от `dem`-файлов, который может быть у каждого плагина (если ему нужно хранить данные в БД), `map`-файл один на всё приложение.

## Дополнительные базы данных

Платформа TeqFW ориентирована на создание “_модульных монолитов_”, но если в приложении нужно иметь дополнительные базы данных, то придётся создавать отдельные загрузчики `dem`-файлов для всех баз данных и выбирать из всего множества `dem`-файлов те, которые относятся к соответствующим базам. После чего сливать `dem`-файлы отдельного подмножества в единую структуру с использованием соответствующего `map`-файла (по одному на каждую базу). Тут уж каждый выкручивается, как может, единого рецепта нет.

## Резюме

*   для каждого плагина описание схемы данных для основной базы находится в файле `./etc/teqfw.schema.json`;
*   для согласования схем данных плагинов между собой используется `map`-файл (один для приложения) — `./etc/teqfw.schema.map.json`;
*   если в приложении используется более одной базы данных, то используются по одному `map`-файлу на БД и требуются кастомные загрузчики для `dem`-файлов;
