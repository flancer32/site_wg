# TeqFW: Термины

Teqfw

Tequila Framework

Glossary

Terms

Эта статья представляет собой словарь терминов, используемых в Tequila Framework, и обновляется время от времени (_версия от_`2020/08/06`).

*   **приложение**: комплекс программ, исполняемых на различном физическом оборудовании (сервера, смартфоны, планшеты, персональные компьютеры), использующий общую кодовую базу, доступную через web.
*   **пакет** (**npm-пакет**): компонент приложения, управляемый [Node Package Manager](https://ru.wikipedia.org/wiki/Npm), из которых и состоит общая кодовая база приложения.
*   **модуль** (**es6-модуль**, **es-модуль**): отдельный файл с исходным JS-кодом, соответствующий требованиям, предъявляемым к [es-модулям](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Guide/Modules).
*   **элемент кода**: JS объект или примитив, который может экспортировать отдельный модуль или пакет.
*   **teq-приложение**: приложение, созданное на базе разрабатываемой платформы [Tequila Framework](https://wiredgeese.com/%D1%87%D1%82%D0%BE-%D1%82%D0%B0%D0%BA%D0%BE%D0%B5-teqfw-208d5938205).
*   **плагин** (**teq-плагин**): npm-пакет, архитектурно совместимый с платформой TeqFW и являющийся базовым строительным компонентом teq-приложений.
*   **дескриптор плагина**: файл `./teqfw.json` с конфигурационной информацией, относящейся к различным компонентам платформы и приложения (DI, CLI, web services, …).
*   **разработчик**: IT-специалист, создающий teq-плагины для различных teq-приложений.
*   **интегратор**: IT-специалист, собирающий конкретное teq-приложение из различных teq-плагинов.
*   **логическое имя модуля**: строка, соответствующая отдельному модулю (`Vendor_Project_Plugin_Path_To_Module`), уникально идентифицирующая данный модуль среди всех остальных модулей приложения. Идентификация элементов кода модуля [производится](https://wiredgeese.com/%D0%B2%D0%BD%D0%B5%D0%B4%D1%80%D0%B5%D0%BD%D0%B8%D0%B5-%D0%B7%D0%B0%D0%B2%D0%B8%D1%81%D0%B8%D0%BC%D0%BE%D1%81%D1%82%D0%B5%D0%B9-%D0%B2-teqfw-b1beb319ca56#fc21) относительно идентификатора самого модуля.
*   **пространство имён**: иерархическая совокупность логических имён всех модулей, создающих кодовую базу приложения.
*   **идентификатор зависимости**: строка, уникально адресующая элемент кода в пределах всего приложения, а также роль элемента кода в качестве зависимости (singleton, new instance).
*   **область кода**(**code area**, **область**, **area**): всю кодовую базу можно разделить на три части по области применения — back (nodejs), front (браузер), shared. В back-области возможно применение инструкции `import` для связывания es6-модулей (в том числе и с `nodejs`-библиотеками), в областях front и shared es6-модули связываются друг с другом посредством [DI-контейнера](https://habr.com/ru/post/562008/) платформы (возможно применение инструкции `import` для связи модулей в пределах одного пакета).
*   **realm** (**риэлм**): “_зона ответственности_” teq-плагина в рамках разделяемого функционала teq-приложения (консольные команды, сервисы и т.п.).

## Адресация ресурсов

Все web-адреса, обрабатываемые teq-приложениями, можно свести к такому виду: `https://domain.com/root/door/space/route`

*   **root**: (опционально) путь к корню teq-приложения в пространстве домена.
*   **точка входа** (**дверь**, **door**): область web-приложения со своими _cookies_ и _service worker_’ами (например, `/pub`, `/admin`).
*   **space**: группа ресурсов одного типа, определяемая соответствующими обработчиком web-запросов (`/src`, `/web`, `/api`).
*   **route**: маршрут ресурса в рамках соответствующего пространства некоторого обработчика запросов (`/css/style.css`, `/load/namespaces`).
