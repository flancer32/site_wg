# Вместе с Виктором Гусевым собран репозиторий @teqfw/github-flows

<zoom-img src="/img/brand/github.png" alt="GitHub" width="100px"></zoom-img>

Вместе с Виктором Гусевым был собран отдельный репозиторий
        [github-flows](https://github.com/viktor-gusev/github-flows)
        для пакета **[@teqfw/github-flows](https://www.npmjs.com/package/@teqfw/github-flows)**. Профиль Виктора доступен здесь:
        [viktor-gusev](https://github.com/viktor-gusev).

Пакет развивает идею предыдущего шлюза
        [Шлюз между GitHub Issues и Codex-агентом](/ru/blog/2026/20260323-01-codex-github-issues-gateway.html)
        и оформляет её как библиотечную основу для веб-приложений, строящих рабочие процессы на базе агентов.
        Теперь речь идёт о перехвате вебхуков с GitHub, извлечении события, подготовке входных данных и запуске
        агентов в Docker-контейнере для обработки этих событий.

Совместные эксперименты с Виктором показали практическую сторону схемы: человек или другой агент может
        запускать производственные цепочки, которые меняют код и доводят его до нового релиза. Это уже не
        исследовательский прототип, а воспроизводимая модель для сборки рабочих процессов.

[@teqfw/github-flows](https://www.npmjs.com/package/@teqfw/github-flows)
        упаковывает этот подход в отдельное переиспользуемое решение. Сам пакет остаётся библиотекой, а
        ответственность за жизненный цикл и окружение лежит на хостовом приложении.
